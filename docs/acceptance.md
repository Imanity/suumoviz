# SuumoViz 验收标准

> 每一步完成时逐项勾选，并在“验收记录”中写明日期、命令与结果。

## 步骤 1：仓库重置与列表页解析

- [x] 旧代码、旧文档、Docker/数据库/前端脚手架已删除，仓库只含新骨架与 docs；
- [x] `python -m pip install -e ".[dev]"` 在干净的 Python 3.12 环境中成功；
- [x] `ruff check .` 无错误；`pytest` 全部通过，且不发出任何网络请求；
- [x] 区汇总页解析：4 个类别的 fixture 解析出的有房源组合数与件数合计和实测一致（49/36,894、43/880、50/12,023、51/8,518），每个有房源的组合都能取得区 URL 名；
- [x] 列表页解析：4 个类别的 fixture 都能解析出总件数和每条房源的 ID、价格、地址、交通、面积、间取，首条房源的字段值与页面一致；
- [x] 最后一页（不足 100 条）解析条数正确；
- [x] 规范化单元测试覆盖：万円、億、円台、区间、未定、徒歩、バス、面积区间、築年月；
- [x] fixture 来自真实页面，已去除脚本，只保留少量条目，电话号码已遮蔽，`tests/fixtures/README.md` 记录来源 URL 与取得日期；
- [x] CI workflow（ruff + pytest）已就绪，GitHub 上首次运行通过。

## 步骤 2：抓取器与轮转计划

- [x] `suumoviz crawl --dry-run --city-html DIR` 完全不发请求、不写文件，打印今天的槽位、页面清单和预计请求数（联网的 `--dry-run` 只发 robots.txt 和 4 个汇总页共 5 个请求）；
- [x] 相邻请求间隔 ≥ 5 秒（测试中用假时钟验证），命令行不允许设得更短；
- [x] 401/403/429/挑战页/robots 不允许时立即停止并写冷却标记，冷却中再次运行直接退出（假服务器测试）；7 天内再次被拦冷却 72 小时；
- [x] User-Agent 为 `Mozilla/5.0 (compatible; SuumoViz/0.1.0)`，不含联系方式，不带 Cookie；
- [x] 单页 404/结构无法识别记为错误并继续，连续 3 页失败停止本轮；5xx/网络错误按 30 秒、60 秒重试；请求数与运行时长超限时停止；
- [x] 轮转：7 天内每个组合的每一页恰好被安排一次；用 2026-11-07 的件数模拟，每天页数在 95–105 之间；新出现的组合分配到负载最低的槽位，已有偏移量不变；
- [x] 本地真实运行一次（`--max-pages 5`），状态码与解析结果正常。

## 步骤 3：数据合并与指标

- [x] 同一天结果重复合并 2 次，`data/` 下所有文件逐字节不变（幂等）；比已合并日期更早的日期拒绝合并；
- [x] 新挂牌、调价、下架、重新上架各有单元测试，下架严格按“15 天未出现且期间成功运行 ≥ 13 次”（第 14 天不下架、第 15 天下架；不足 13 次成功运行时不下架）；
- [x] 每日件数覆盖全部组合（包括 0 件），质量门槛不通过时也照常记录；
- [x] 质量门槛不达标时房源、事件、统计都不写入，`runs.csv` 记录 `merged=false` 和原因；页头件数偏差、条数不符、字段解析率各有测试；
- [x] 每日抽样统计的样本数与当天抓到的条目数一致；全量统计只含 `active` 房源；土地类房源不计入单价；
- [x] 用真实的完整一天数据运行 `suumoviz daily`，质量门槛通过并成功合并。

## 步骤 4：GitHub Actions 定时运行

- [x] 试探 workflow 在 GitHub runner 上成功访问 robots.txt、4 个汇总页和 1 个列表页，无 403/429/验证码；
- [x] 手动触发每日 workflow（`max_pages=5`）跑通全链路：抓取 → 合并 → 提交到 `data` 分支 → 上传 artifact；
- [ ] 每日 workflow 由定时触发连续 3 天成功，`data` 分支每天一次提交；
- [x] 人为制造冷却标记后，下一次运行跳过且不发请求、不提交；
- [x] 日志中没有房源内容（只有“类别 区代码 页号：条数”和汇总 JSON）；
- [ ] 完整槽位（约 100 页）在 GitHub runner 上单次运行用时 ≤ 20 分钟；
- [ ] 失败时 GitHub 邮件通知送达（定时任务的通知发给最后修改 cron 的用户；遇到第一次失败时确认）。
