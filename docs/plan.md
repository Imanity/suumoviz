# SuumoViz 实施计划

> 基线日期：2026-11-07。本计划替代旧版 docs/00–09（旧代码保存在提交 `8e744fa`）。
> 2026-11-07 仓库更名为 `Imanity/suumoviz-data`（私有，采集与数据）；前端在公开仓库 `Imanity/suumoviz`。
> 2026-11-19 起两者合并为公开仓库 `Imanity/suumoviz`：数据逐行编码混淆后放在 `data` 分支，网页只展示区域均价（步骤 8）。
> 设计细节见 [design.md](./design.md)，各步骤验收标准见 [acceptance.md](./acceptance.md)。

## 1. 目标

每天自动采集一次东京都 SUUMO 在售房源的**列表页**，按“7 天轮转”方式每天只扫约 1/7，
每 7 天覆盖全部房源一次，产出：

- 每天、每个区市町村 × 每个类别的精确在售件数；
- 每套房源的当前状态、新挂牌、调价、下架事件；
- 每个区 × 类别的价格统计（每日抽样 + 7 天滚动全量）；
- 一个在地图上查看分布与趋势的静态 Web 页面。

## 2. 范围

| 项目 | 决定 |
|---|---|
| 地域 | 东京都全部区市町村 |
| 类别 | 中古マンション、新築マンション、新築一戸建て、中古一戸建て |
| 页面 | 只抓列表页（每页 100 件），不抓详情页 |
| 频率 | 每天 1 次，日本时间凌晨 |
| 扫描量 | 每天约 100 个列表页 + 5 个辅助请求（全量约 700 页的 1/7） |
| 请求间隔 | 5 秒，单连接 |
| 运行环境 | 公开 GitHub 仓库 `Imanity/suumoviz` + GitHub 托管 runner（步骤 8 前为私有仓库） |
| 数据存放 | 同仓库的 `data` 分支（CSV，逐行编码混淆） |
| 前端 | 同仓库 `web/` + GitHub Pages；只发布按区域汇总的均价（编码后的 `summary.dat`） |

不做：租赁、详情页、土地、图片、经纪公司联系方式、跨中介同一房源合并（列入后续可选）。

## 4. 每一步的工作内容

### 步骤 1：仓库重置与列表页解析

- 删除旧代码、旧文档、Docker/数据库/前端脚手架；
- 新 Python 包 `suumoviz`（Python 3.12，依赖只有 `lxml`）；
- 类别配置：URL 路径、排序参数、页面布局类型；
- 解析器：区汇总页（区代码、名称、URL 名称、件数）、列表页（总件数、每条房源字段）；
- 文本规范化：价格（万円/億/円台/区间/未定）、面积、交通、築年月；
- 从真实页面裁剪的 fixture（去脚本、只保留少量条目、遮蔽电话号码）；
- CI：ruff + pytest。

### 步骤 2：抓取器与轮转计划

- HTTP 客户端：固定 UA、5 秒间隔、超时、5xx 有限重试；
- 停机规则：401/403/429、验证码/挑战页、robots 不再允许 → 立即停止并写冷却标记；
- 轮转：由区汇总页件数算出每个“区 × 类别”的页数，按偏移量把页分到 7 天；
- `suumoviz crawl` 命令：只抓“今天”的页，输出当天解析结果；支持 `--dry-run`（只打印计划）和 `--max-pages`。

### 步骤 3：数据合并与指标

- 合并当天结果到房源状态表，生成新挂牌/调价/下架/重新上架事件；
- 每日件数、每日抽样统计、运行日志；
- 质量门槛不达标时不合并数据，运行标记为失败。

### 步骤 4：GitHub Actions 定时运行

- 每日 workflow（UTC 18:17 = 日本时间 03:17）：检出代码与 `data` 分支 → 运行 → 提交数据；
- 手动触发的试探 workflow：在 GitHub runner 上发十几个请求验证可访问性；
- 冷却期内自动跳过；失败时由 GitHub 邮件通知。

### 步骤 5：地理编码与聚合输出

- 下载国交省“位置参照情報”（大字・町丁目レベル，东京都），精简后随代码发布，按町丁目匹配坐标；
- `suumoviz build` 生成给 Web 用的静态 JSON：房源（引用町丁目代表点）、区域代表点、区 × 类别趋势序列；
- 顺带补充：列表页解析保留详情页路径（Web 可直接链接到 SUUMO）；统计增加全东京汇总行。

### 步骤 6：地图 Web

- 静态站点（Vite + React + MapLibre GL JS + 地理院タイル），代码在公开仓库 `Imanity/suumoviz`，GitHub Pages 发布；
- 数据仓库每天把 JSON 推送到 `site` 分支；页面用访问者的只读 Token 经 GitHub API 读取，公开仓库和 Pages 上没有数据；
- 类别/价格/面积筛选、町丁目聚合点、区 × 类别趋势图。

### 步骤 7：试运行与验收

- 连续运行 14 天，核对轮转覆盖率、请求量、下架判定、GitHub 用时；
- 写运行手册（冷却后如何恢复、解析器失效如何处理）。

### 步骤 8：合并为公开仓库

- 采集代码（Python 包、测试、工具、文档、workflow）并入公开仓库 `Imanity/suumoviz`，网页移到 `web/`；
- `codec.py`：`data/` 下的 CSV、每日快照、测试样本、网页数据逐行编码混淆（见 design.md 5.2）；
- `suumoviz build` 只输出区域汇总 `summary.dat`；网页简化为区域均价地图 + 排行，不再需要 Token；
- `pages.yml` 从 `data` 分支生成汇总并发布 Pages，每日采集后自动调用；
- 迁移：停用私有仓库的定时采集 → 私有 `data` 分支的历史逐个提交重放（CSV 编码）到公开 `data` 分支 → 合并 `main`。

## 5. 已确认的决策

| 决策 | 结论 | 依据 |
|---|---|---|
| 只抓列表页 | 是 | 列表页已含价格、地址、车站、面积、间取、築年月等核心字段 |
| 每页件数 | 100（上限，`pc=200` 无效） | 2026-11-07 实测 |
| 轮转周期 | 7 天 | 用户决定；每天约 100 页 ≈ 全量 1/7 |
| 列表 URL | 按区路径 `/{类别}/tokyo/sc_{区}/` | robots 禁止全东京列表 `JJ010FJ001`、`JJ012FC001` |
| 排序 | 地址升序（新築マンション除外） | 地址顺序最稳定，轮转分页不易漂移 |
| 间隔 | 5 秒 | 用户决定 |
| 仓库 | 私有仓库 + GitHub 托管 runner | 数据不外泄；每月用时约 400 分钟，在免费额度内 |
| 地图坐标 | 町丁目代表点（国交省位置参照情報 令和 7 年） | 免费、可加工；列表页地址只到丁目，再细没有意义 |
| 地图 | MapLibre GL JS + 地理院タイル（淡色） | 用户决定用开源地图；无需 key，日文标注 |
| 前端部署 | 公开仓库 Pages，数据与代码同仓库（2026-11-19 起） | 用户决定合并为一个公开仓库；此前为私有仓库 `site` 分支 + 只读 Token |
| 数据保护 | 逐行 XOR + base64 编码混淆，不用 SQLite | 用户要求不能直接阅读；按行编码保持每天的 git 差异小，SQLite 二进制每天整体变化 |
| 网页内容 | 只发布区域汇总（均价、中位价、单价均价、套数） | 用户要求最基础的地图与区域均价；不发布单条房源 |

## 6. 主要风险

| 风险 | 应对 |
|---|---|
| GitHub runner 的机房 IP 被 SUUMO 拦截 | 步骤 4 先跑试探 workflow；被拦则改用自托管 runner |
| 页面结构改版导致解析失败 | 质量门槛拦截坏数据；fixture 测试；失败邮件通知 |
| 分页边界漂移导致个别房源某轮漏看 | 下架需连续 2 个周期（15 天）未出现 |
| SUUMO 利用规约限制 | 网页只展示区域汇总统计；原始数据在公开仓库中编码存放，但编码可还原，任何人都能下载 `data` 分支 |
| 公开仓库 60 天无活动时 GitHub 停用定时 workflow | 每天的 `data` 提交算作活动；若被停用，在 Actions 页面重新启用 |
